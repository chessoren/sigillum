Method 1.0 · open, versioned, contestable

Sovereignty is not declared. It is proven.

Five questions, one scale, three rules. Everything below is implemented in score.py — the language model never sets the grade.

The scale

  • AFully sovereign. Runs on hardware the organisation controls, nothing leaves, works offline (tested), no third party, reproducible.
  • BLargely sovereign. Swiss infrastructure, or local but not yet proven offline.
  • CPartial or unproven. Depends on deployment, destinations that cannot be located, or claims without traces.
  • DForeign dependencies. Usage metadata or an open model served abroad; telemetry on by default.
  • EDependent on foreign services. User content goes abroad to a closed model or a tracker; offline, everything stops.
  • ?Unknown. Shown as such, never guessed. It caps the final grade at C.

Rule 1 — the proof rule

A claim without a trace is not proof. If a README says "everything runs locally" and nothing in the code shows it, the question cannot exceed C. Every answer cites evidence IDs that point to a file and a line, so anyone can open them and disagree.

Rule 2 — the weakest link

The final grade is the worst of the five answers. A project that is perfect on four questions but sends data abroad cannot be A. A strict, reliable signal beats a flattering average.

Rule 3 — a dated seal

Every seal carries the date, the commit examined, the method and registry versions, and a SHA-256 fingerprint of the graded content (python -m sigillum verify report.json). It expires after 90 days.

The role of Apertus

Apertus does what fixed rules cannot: it reads the documentation to extract what the project claims, sets each claim against the traces and names the gaps, and explains the verdict in plain German, French, Italian and Romansh. Every answer is checked: quotes must exist word for word, evidence IDs must exist, a line in the wrong language is rejected. Rejected answers are counted in the report. Apertus runs locally (llama.cpp, Apertus v1.5 8B) or on any endpoint set with LLM_BASE_URL — the report shows the endpoint's jurisdiction.

Ethics

  • 1Only public projects. Nothing private is ever examined.
  • 2Aggregated and anonymous. The community audit is written as proportions only; the code cannot output names.
  • 3Right of reply first. A project is named only if its team requested or accepted the seal after reading the report.
  • 4A service, not a trial. Any team can request its free examination, with the detailed report and the fixes.
  • 5Sigillum first, on itself. Its own seal, limits and flaws are published first.

Sigillum is a transparency instrument. It is not a legal label, not an official certification, and not affiliated with the Swiss Confederation.

Published limits

  • !Static analysis only: behaviour that appears only at runtime (dynamic URLs, plugins) can be missed. A runtime probe is the next step.
  • !The registry of destinations is curated by hand and incomplete; unknown hosts are reported as unknown, never as safe.
  • !Hyperlinks are excluded heuristically (href, Markdown links); a script that fetches such a URL could be missed.
  • !Apertus 8B (quantised, CPU) writes German and Romansh with occasional errors; Romansh lines should be proof-read by a native speaker.
  • !Build-time downloads (base image, model weights) are listed but do not lower the runtime grade.
  • !Exclusions in .sigillumignore are self-declared; they are published in every report so that readers can judge them.

Source code

Apache-2.0 code, CC-BY-4.0 report. Python standard library only, no runtime dependency. make run starts Sigillum and a local Apertus in Docker; make offline-test examines all samples with networking disabled.

Méthode 1.0 · ouverte, versionnée, contestable

La souveraineté ne se déclare pas. Elle se prouve.

Cinq questions, une échelle, trois règles. Tout ce qui suit est implémenté dans score.py — le modèle de langue ne fixe jamais la note.

L'échelle

  • APleinement souverain. Tourne sur un matériel que l'organisation contrôle, rien ne sort, marche hors ligne (testé), aucun tiers, reproductible.
  • BLargement souverain. Infrastructure suisse, ou local mais pas encore prouvé hors ligne.
  • CPartiel ou non prouvé. Dépend du déploiement, destinations qu'on ne sait pas situer, ou affirmations sans trace.
  • DDépendances étrangères. Métadonnées d'usage ou modèle ouvert servi à l'étranger ; télémétrie active par défaut.
  • EDépendant de l'étranger. Le contenu des utilisateurs part à l'étranger vers un modèle fermé ou un traceur ; hors ligne, tout s'arrête.
  • ?Inconnu. Affiché comme tel, jamais deviné. Il plafonne la note finale à C.

Règle 1 — la règle de la preuve

Une affirmation sans trace ne vaut pas une preuve. Si un README dit « tout est local » et que rien dans le code ne le montre, la question ne dépasse pas C. Chaque réponse cite des identifiants de preuve qui pointent vers un fichier et une ligne : chacun peut les ouvrir et contester.

Règle 2 — le maillon faible

La note finale est la plus mauvaise des cinq réponses. Un projet parfait sur quatre questions mais qui envoie ses données à l'étranger ne peut pas être A. Mieux vaut un signal sévère et fiable qu'une moyenne flatteuse.

Règle 3 — un sceau daté

Chaque sceau porte la date, le commit examiné, les versions de la méthode et du registre, et une empreinte SHA-256 du contenu noté (python -m sigillum verify rapport.json). Il expire après 90 jours.

Le rôle d'Apertus

Apertus fait ce qu'une règle fixe ne sait pas faire : il lit la documentation pour en tirer ce que le projet affirme, confronte chaque affirmation aux traces et nomme les écarts, puis explique le verdict en allemand, français, italien et romanche simples. Chaque réponse est contrôlée : les citations doivent exister mot pour mot, les identifiants de preuve doivent exister, une ligne dans la mauvaise langue est rejetée. Les rejets sont comptés dans le rapport. Apertus tourne en local (llama.cpp, Apertus v1.5 8B) ou sur tout point d'accès fixé par LLM_BASE_URL — le rapport affiche sa juridiction.

Éthique

  • 1Seulement du public. Rien de privé n'est jamais examiné.
  • 2Agrégé et anonyme. Le bilan communautaire n'est écrit qu'en proportions ; le code ne peut pas produire de noms.
  • 3Le droit de réponse d'abord. Un projet n'est nommé que si son équipe a demandé ou accepté le sceau après avoir lu son rapport.
  • 4Un service offert, pas un procès. Toute équipe peut demander son examen gratuit, avec le rapport détaillé et les corrections.
  • 5Sigillum d'abord sur lui-même. Sa propre note, ses limites et ses failles sont publiées en premier.

Sigillum est un instrument de transparence. Ce n'est ni un label juridique, ni une certification officielle, et il n'est pas affilié à la Confédération suisse.

Limites publiées

  • !Analyse statique uniquement : un comportement qui n'apparaît qu'à l'exécution (URL dynamiques, plugins) peut échapper. Une sonde à l'exécution est la prochaine étape.
  • !Le registre des destinations est tenu à la main et incomplet ; un hôte inconnu est signalé comme inconnu, jamais comme sûr.
  • !Les liens hypertextes sont exclus par heuristique (href, liens Markdown) ; un script qui appellerait une telle URL pourrait échapper.
  • !Apertus 8B (quantifié, sur CPU) écrit l'allemand et le romanche avec des erreurs occasionnelles ; les lignes en romanche doivent être relues par un locuteur natif.
  • !Les téléchargements à la construction (image de base, poids du modèle) sont listés mais n'abaissent pas la note d'exécution.
  • !Les exclusions de .sigillumignore sont auto-déclarées ; elles sont publiées dans chaque rapport pour que le lecteur en juge.
